# OpenJob 产品与使用指南

> 适用版本：当前 `main` 分支。OpenJob 是本地运行的个人求职工作台；它不是云端代投服务，也不应被用作无人值守的大规模外发工具。

## 1. 产品背景与定位

求职中最消耗精力的部分通常不是“做出是否投递的判断”，而是围绕判断产生的重复工作：反复搜索相似岗位、比对 JD、修改同一份简历、记录联系状态，以及在多个页面之间切换。

OpenJob 将这些准备动作放进一个本地工作台：

```text
专用 Chrome 中的招聘平台
        ↓
采集、去重、筛选、AI 评分
        ↓
岗位池与人工确认队列
        ↓
真实底稿 + XLSX 经历素材 → 定制简历 / 招呼语草稿
        ↓
人工确认后，才在支持的平台执行发送
        ↓
回复监测与个人跟进记录
```

它的核心分工很明确：

- OpenJob 负责重复、可检查的准备工作；
- 求职者负责目标设定、简历真实性、投递判断和最终外发确认；
- 平台账号、简历文件、素材库和数据库默认都留在本机。

### 适合谁

- 正在集中找实习、校招或社招岗位，希望每天获得一批待审核职位的人；
- 已有 Word 简历底稿，希望针对 JD 更高效地制作多个版本的人；
- 有项目、奖项、学生工作等经历，希望维护为长期可复用素材库的人；
- 希望保留账号控制与人工确认，而不是交给黑箱代投的人。

### 不适合拿来做什么

- 不能替代个人判断、背景核验或正式职业建议；
- 不应绕过招聘平台规则、验证码或风控措施；
- 不提供手机直连公网控制；Web 工作台当前只绑定 `127.0.0.1`；
- 不支持不经审核地自动投递、自动发招呼语、自动发简历或自动回复 HR。

## 2. 开始前的准备

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 推荐 Windows；macOS / Linux 可用于本地开发，浏览器自动化需自行验证 |
| Python | 3.10 或更高版本 |
| 浏览器 | Google Chrome；建议使用 OpenJob 专用 Profile |
| AI 服务 | 至少配置一个兼容服务的 API Key（默认 DeepSeek） |
| 网络 | 能正常访问所选招聘平台与 AI 服务 |

### 安装与首次启动

在仓库根目录执行：

```bash
pip install -e .
python scripts/setup.py
openjob web
```

工作台默认打开在：

```text
http://127.0.0.1:8686
```

`config.yaml` 是个人本地配置，含 API Key 时绝不能提交到 Git。项目已将它排除在版本控制之外。

Windows 用户希望以一次点击启动专用 Chrome 与工作台时，可以按 [Windows 一键启动器说明](windows-launcher.md) 创建桌面快捷方式。

## 3. 连接专用 Chrome

OpenJob 需要连接一个开启远程调试端口的 Chrome，才能读取招聘平台中你已登录的会话。建议不要用日常浏览器 Profile，以避免工作任务与个人浏览相互干扰。

1. 关闭所有 Chrome 窗口；
2. 启动专用 Chrome，并启用调试端口，例如：

   ```bash
   chrome --remote-debugging-port=9222
   ```

3. 在该 Chrome 中自行登录目标招聘平台；
4. 打开工作台，在配置或任务区域确认浏览器连接正常；
5. 第一次只以 **1 个关键词、1 个城市、1 页** 跑“采集 + 自动评分”验证。

如果 Windows 找不到 `chrome` 命令，请使用上面的桌面启动器，或从 Chrome 安装目录运行 `chrome.exe`。不要把调试端口暴露给局域网或公网。

## 4. 一条安全、可重复的日常工作流

### 第一步：定义搜索范围

在配置页设置：

- 目标岗位关键词；
- 城市；
- 实习 / 社招偏好；
- 评分阈值；
- 不接受的公司或 JD 关键词；
- 采集平台与单轮最大页数。

建议先从少量高意图关键词开始，例如“数据分析实习”“商业分析实习”“AI 产品实习”，而不是把完全不同方向堆进同一轮任务。这样评分理由更可读，人工审核也更快。

### 第二步：采集与评分

从工作台启动“采集 + 自动评分”。系统会：

1. 采集符合当前范围的岗位；
2. 按岗位来源去重并入库；
3. 使用职责匹配、证据强度、硬性要求、工具技能、实际可行性五个维度评分；
4. 在任务卡中展示采集与 AI 评分的实时进度；
5. 将符合阈值的岗位留给人工审核。

评分只是排序建议。低分并不必然意味着不能投，高分也不代表岗位真实、合适或值得接受。

### 第三步：审核岗位和生成材料

在岗位池中阅读 JD、评分理由和原平台链接，必要时直接拒绝或加入黑名单。对值得继续的岗位：

1. 选择正确的 Word 简历底稿；
2. 检查系统引用的经历和 JD 匹配理由；
3. 生成定制简历和招呼语草稿；
4. 打开并人工审阅简历，核对所有事实、数字、时间和表述；
5. 只有满意时才加入确认队列。

### 第四步：确认发送与跟进

确认队列是外发动作的最后一道门：

- 在支持发送的平台，检查岗位、招呼语和简历后再确认；
- 在不支持自动发送的平台，使用原平台链接自行投递，并回到工作台标记状态；
- 工作台会应用每日上限、发送时间窗与间隔等配置；这些限制是保护措施，不是对账号安全的保证；
- 收到 HR 回复后，以平台内沟通为准，并在工作台维护自己的下一步行动。

## 5. 工作台内定时采集

定时采集的定位是“你打开工作台期间的低干扰批处理”，不是系统级后台机器人。

在 **配置页 → 定时采集** 设置：

- 启用 / 暂停；
- 每日执行时间，例如 `09:30`、`19:30`；
- 仅工作日或每天；
- 每轮每个平台最大搜索页数；
- 参与的平台（默认 BOSS 直聘）；
- “今日暂停”。

执行规则：

- 只有 OpenJob 工作台和专用 Chrome 都在运行时，调度器才会工作；
- 到点只执行 **采集 + 自动 AI 评分**，完成即停止；
- 不会自动投递、发招呼语、发简历、跟进或回复；
- 任务错过时间、Chrome 未连接、风控锁生效、已有任务运行或超过额度时，本轮会被记录为跳过，不会补跑；
- 同一个时点每天最多执行一次，重启工作台也不会重复执行已经完成的时点。

首页的“计划任务”卡会显示下一次执行时间、今日执行次数、最近一次状态、新增岗位数、高分岗位数和跳过原因。

## 6. 用 XLSX 建立自己的简历素材库

素材库用于给简历优化提供可验证的事实来源，尤其适合维护项目、奖项、实习、学生工作、技能证据与成果数据。

### 推荐：标准模板

在 **配置页 → 简历素材库 → 下载模板** 下载 `.xlsx`，填写：

- `id`：稳定且唯一的素材标识；
- `type`：素材类别；
- `title`：一句话标题；
- `description`：可用于简历的具体描述；
- 其余字段按需补充。

### 已有 Excel：智能导入

如果已经有自己的表格，选择 **导入自己的 Excel（智能识别）**：

1. 上传 `.xlsx` 文件；
2. 系统识别工作表、表头行和常见中文字段别名；
3. 检查字段映射和行预览；
4. 排除不完整或不想使用的行；
5. 确认导入。

导入会先生成预览，确认前不会覆盖现有素材库。`title` 和 `description` 是最终必需字段；旧版 `.xls` 请先转换为 `.xlsx`。不要把密码、身份证号、私人联系方式等无关敏感信息写入素材库。

## 7. 平台能力矩阵

不同平台的自动化能力不同。“支持多平台”不表示每个平台都能一键投递。

| 平台 | 岗位采集 | AI 评分 | 招呼语生成 | 自动化发送 | HR 回复监听 |
| --- | --- | --- | --- | --- | --- |
| BOSS 直聘 | 支持 | 支持 | 支持 | 支持，仍需人工确认 | 支持 |
| 智联招聘 | 支持 | 支持 | 支持 | 不支持 | 不支持 |
| 前程无忧 | 支持 | 支持 | 支持 | 不支持 | 不支持 |

对于智联招聘和前程无忧，OpenJob 可以沉淀岗位、评分、简历与招呼语参考，但实际投递要在原平台手动完成。

## 8. 数据、安全与边界

- Web 工作台默认只监听 `127.0.0.1`；当前不提供安全的局域网或公网访问能力；
- 招聘平台登录态保存在你的专用 Chrome Profile 中；不要共享该 Profile 或调试端口；
- `data/`、`config.yaml`、简历文件与本地数据库不应提交到 Git；
- API Key 优先通过本地配置或环境变量提供，界面只应展示脱敏值；
- 自动化访问招聘平台可能触发限制甚至影响账号，请遵守平台规则、降低频率、及时查看任务状态；
- OpenJob 的限制、随机等待和风险锁是减轻操作强度的措施，不构成账号安全承诺。

详细风险建议见 [风险与使用守则](risk-guide.md)。

## 9. 常见问题

### 工作台打不开

确认终端仍在运行 `openjob web`，然后访问 `http://127.0.0.1:8686`。若端口被占用，可改用：

```bash
openjob web --port 8687
```

### 采集任务显示 Chrome 未连接

确认专用 Chrome 仍在运行、已使用调试端口启动，并已登录目标招聘平台。不要把普通 Chrome 与专用 Chrome 混为同一个 Profile。

### 定时任务没有执行

依次检查：是否开启定时采集、是否至少配置了一个 `HH:MM` 时间、工作台是否正在运行、专用 Chrome 是否可连接、当天是否暂停、当前是否已有任务在执行。首页计划任务卡会给出最近一次跳过原因。

### AI 评分或简历生成失败

先确认 API Key、模型名称、网络和余额/配额；再检查配置页的模型设置。任务详情中会保留阶段和错误信息，但不应把 API Key 贴到 Issue 或截图中。

### 更新后界面看起来没有变化

重启 `openjob web`，然后在浏览器中使用 `Ctrl + F5` 强制刷新。若从源码运行前端开发环境，重新执行 `npm install` 与 `npm run build`。

## 10. 给贡献者的质量基线

提交 PR 前至少运行：

```bash
python -m pytest -q
ruff check src/ tests/ --select=E9,F63,F7,F82
cd src/openjob/web/frontend
npm ci
npm run build
node scripts/ui-acceptance.cjs
```

更多贡献规则见 [贡献指南](../CONTRIBUTING.md)。不要提交真实简历、`config.yaml`、数据库、浏览器 Profile、API Key 或招聘平台会话信息。
