# 风控使用守则

> 本工具自动化访问招聘平台，**可能违反各平台用户协议**。以下守则是把风险压到最低的底线，
> 违反任意一条，账号被风控/封禁的风险都会显著上升。请逐条遵守。

## 一、账号策略

1. **先用小号/不重要的账号验证全流程**，确认稳定后再考虑主账号。不要在主力求职账号上做首次实验。
2. **只用自己的账号**，绝不把工具给他人代投——多账号共用设备/工具是风控重灾区。
3. OpenJob 通过**专用 Chrome 配置**（桌面图标启动的窗口）连接你的已登录会话，不保存账号密码。
   不要把这个专用窗口和日常浏览器混用，也不要在专用窗口里登录无关网站。

## 二、频率红线（已内置，不要调松）

| 参数 | 默认值（config.yaml） | 说明 |
| --- | --- | --- |
| 每日发送上限 | `throttle.daily_limit: 10` | 每天最多 10 条招呼语；海投=自杀 |
| 发送间隔 | `interval_min: 90` ~ `interval_max: 240` 秒 | 高斯随机分布，模拟真人节奏 |
| 发送时间窗 | `send_windows: ["09:00-16:00"]` | 窗口外投递任务自动拒绝/截止 |
| 搜索页上限 | `collection.daily_search_page_limit: 60` | BOSS 单日翻页安全线 |
| 详情页上限 | `collection.daily_detail_page_limit: 150` | 触达后当天自动停止 BOSS 采集 |

> ⚠ **实测教训（2026-08-13，V1 时期）**：无头浏览器 1 分钟内连续搜索 2 次，BOSS 即返回
> code 36「账户异常行为」软风控。结论：
> 1. BOSS 对无头浏览器 + 高频请求极其敏感——OpenJob 全程使用**可见浏览器**（你的真实 Chrome），
>    这本身就是最重要的防线，不要尝试改造为无头模式；
> 2. 同一平台两次操作之间**至少间隔几分钟**，宁可慢；
> 3. 收到 code 36 后立即停止当天自动化，用 App 正常使用后风控自动解除，无需恐慌。

> ⚠ **实测验证（2026-08-29）**：单日详情页触达 150 页上限后系统自动停止采集，
> 该保护按设计工作。**不要调高这两个上限**——它们是账号安全和采集质量的双重保险。

## 三、操作原则

1. **半自动是本工具的底线**：投递永远人工确认（面板勾选 + 发送）。不要为了"全自动"改造代码——
   全自动是封号的最快路径。所有发送类操作（招呼语、简历、回复）代码层面均有人工闸门，请勿绕过。
2. **风控信号即停**：界面报「安全验证/操作频繁/账号异常」时，立刻停止当天操作，
   人工登录平台确认账号状态，至少间隔 24h。监听任务检测到验证码/限流会自动全局安全锁。
3. **人工节奏**：模拟真实求职者的行为——发送限制在时间窗内、单次投递数量克制、
   不要在凌晨/通宵批量跑。系统已强制时间窗，请勿修改。
4. **遇到验证码人工处理**：验证码的存在就是平台在说"停下来"。不要集成任何自动打码/绕过服务。
5. **不要绕过去重守卫**：发送前的会话级去重（会话已有我方消息即跳过）是保护 HR 体验
   和账号信誉的机制，绕过它等于给自己埋雷。

## 四、数据与隐私

1. 本工具所有数据（岗位库、简历、投递记录、AI 用量）都在本地 `data/` 目录，
   **不要上传到任何公开仓库**——简历和登录态都属于敏感个人信息。
2. 自动备份保存在 `data/backups/`（保留最近 7 份），同样属于敏感数据，勿外传。
3. API Key 只存在本地 `config.yaml`（已在 .gitignore），配置接口对外只回显掩码 `sk-****`。
4. 本项目如放 GitHub，请保持**私有仓库**。

## 五、法律与道德提示

1. 各平台用户协议均禁止自动化访问与投递，账号风险自负。
2. 本工具定位为**个人求职辅助**：帮你看清市场、管理投递节奏、准备沟通内容——
   不是批量海投机器，也不应用于任何商业代投场景。
