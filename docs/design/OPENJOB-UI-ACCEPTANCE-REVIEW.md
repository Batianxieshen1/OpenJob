# OpenJob UI 2.0 验收报告与第二轮优化指令

> 验收对象：当前 `main` 分支 UI 重构结果  
> 验收基准：参考图的悬浮 App Shell、窄侧栏、胶囊导航、不对称 Bento、轻量数据可视化，以及“高级、灵动、丝滑”的体验目标。  
> 验收视口：1280×720、1024×768、390×844；浅色与深色主题。  
> 构建结果：`npm run build` 已通过。

## 1. 总体结论

**结论：有条件通过，但不建议把当前版本视为最终完成版。需要进行第二轮视觉与交互收口。**

- 首页首屏完成度：约 **75%**。
- 全站视觉一致性：约 **60%–65%**。
- 桌面端核心可用性：存在阻断问题，修复后才能正式通过。
- 移动端：当前不通过。

做得较好的部分：

1. 已形成浅灰画布、白色悬浮 App Shell 和窄图标侧栏。
2. 顶部胶囊导航、Hero、近 7 日图表和自动化控制卡的方向正确。
3. 黑白灰配钴蓝的色彩策略与参考图相符。
4. 首页首屏的内容层级和品牌感相比旧版提升明显。
5. 深色主题整体可以工作，基础路由和主题切换正常。

当前最大问题不是“风格完全错误”，而是：**首页只重做了一部分，业务页面和复杂交互仍然停留在旧后台形态，并且存在两个关键 UI 功能缺陷。**

## 2. P0：必须立即修复的阻断问题

### P0-1 投递确认页的岗位详情弹窗实际不可见

**页面：** `/confirm`

点击第一张岗位卡的“查看详情”后，页面只出现整页灰色遮罩，详情卡没有出现在当前视口。用户无法查看详情，也无法正常点击关闭。

根因已经定位：

- `ConfirmQueuePage` 根容器使用了 `.rise-in`；
- `.rise-in` 动画结束后仍保留 `transform: translateY(0)`；
- 带 transform 的祖先会改变后代 `position: fixed` 的包含块；
- `JobDetailModal` 因此相对于约 14,000px 高的页面内容定位，并被居中到视口之外。

相关文件：

- `src/openjob/web/frontend/src/globals.css` 第 123–135 行；
- `src/openjob/web/frontend/src/pages/ConfirmQueuePage.tsx` 第 90 行、第 150 行；
- `src/openjob/web/frontend/src/pages/DashboardPage.tsx` 第 963–994 行。

**修复要求：**

1. 所有 Dialog、Drawer、Toast、Popover 等浮层使用 React Portal 挂载到 `document.body`。
2. 页面级入场动画结束后不得让页面根容器长期保留 transform；可用只保留 opacity 的页面动画，或动画结束后清除 transform。
3. 弹窗必须有 `role="dialog"`、`aria-modal="true"`、标题关联、Esc 关闭、点击遮罩关闭和焦点锁定。
4. 在页面顶部、中部和底部滚动位置分别测试打开弹窗，弹窗都必须固定在视口内。

**验收标准：** 1280、1024 和 390 宽度下，任意滚动位置打开岗位详情，详情面板均可见、可滚动、可关闭。

### P0-2 岗位池表格在 1280px 下已经严重失真

**页面：** `/jobs`

当前表格塞入 11 列，城市、薪资、学历、状态、活跃时间等字段被压成逐字或两三个字一行。一条岗位记录高度接近 140px，无法快速扫读，已经不符合桌面工作台的使用效率。

**修复要求：**

推荐改为“主信息列表 + 右侧详情抽屉”，不要继续强行展示 11 列：

- 默认保留：选择、公司/职位、城市、薪资、匹配分、状态、时间、操作；
- 学历、招聘类型、招聘者活跃度合并到职位副信息或详情抽屉；
- 公司与职位组成一个主信息单元，不要占两列后再压缩其他信息；
- 匹配分用醒目的数字或小型环形/进度视觉；
- 操作只保留主操作和 `···` 更多菜单；
- 1280px 下禁止出现中文逐字纵向折行；
- 若仍保留表格，至少设置合理 `min-width` 并使用表格自身横向滚动，而不是压垮每列。

**验收标准：** 1280px 下单行高度控制在约 64–80px，职位和公司可一眼扫读，表头不出现逐字换行。

## 3. P1：本轮必须完成的核心体验问题

### P1-1 投递确认页一次性渲染全部 142 张岗位卡

实测：

- 主内容高度约 **14,053px**；
- DOM 元素约 **3,269 个**；
- 按钮约 **432 个**；
- 复选框 **142 个**。

这会造成页面极长、操作定位困难、动画和渲染负担大，也让“人工确认闸门”变成无穷列表。

**优化要求：**

- 增加分页，每页建议 12–20 条；或使用虚拟列表；
- 顶部批量操作栏做 sticky；
- 增加“高匹配 / 今日活跃 / 待确认 / 已确认”等快捷筛选；
- 首屏优先展示高分和高活跃岗位；
- 卡片正文只显示 2 行摘要，详细评分理由进入抽屉；
- 选中状态要比目前更明显，但不要整卡高饱和着色。

### P1-2 移动端布局不通过

在 390×844 下：

- 左侧 76px 侧栏仍常驻；
- 顶部四个胶囊导航被压成竖排单字；
- Hero 标题、日期和按钮出现不自然断行；
- 首页 `main` 存在内部横向溢出；
- 岗位池的标题、说明、回收站和筛选区被压成狭窄长列。

**优化要求：**

- `< 768px` 隐藏桌面侧栏，改为底部导航或抽屉菜单；
- 顶部胶囊导航在移动端改成横向可滚动 Tabs，或只显示当前页标题与菜单按钮；
- Hero 操作按钮改为 1 个主按钮 + 2 个图标快捷操作，禁止文字逐字折行；
- Bento 卡片全部单列，统一间距 12–16px；
- 筛选器改为“筛选”按钮打开 Bottom Sheet，不在页面直接展开全部输入项；
- 表格在移动端改成岗位卡片列表。

### P1-3 首页仍然过长，首页与确认页职责重复

首页主内容高度约 **2,193px**；1024px 宽度下约 **2,803px**。首页下半部分继续展示完整筛选器、批量操作和 6 张详细岗位卡，导致首页再次变成业务列表页。

**优化要求：**

首页只保留三类信息：

1. 今天是否需要行动；
2. 当前流程运行到哪里；
3. 最值得处理的 3–5 个事项。

建议：首页待确认区只展示 3 个最高优先岗位，每张只保留职位、公司、分数、薪资、活跃度和一个主操作；完整筛选、全选、批量投递全部移到 `/confirm`。

### P1-4 首页上半部分和下半部分设计语言断层

Hero 和首排 Bento 已是新视觉，但继续向下后重新出现：

- 五张同规格 KPI 卡；
- 旧式 AI 用量横条；
- 大面积空白的 HR 简历事项；
- 完整筛选表单和普通岗位卡。

这使页面看起来像“新首页拼接旧后台”，不是完整的 UI 2.0。

**优化要求：** 重构第二排 Bento，而不是给旧模块换圆角外壳：

- 事项卡：待确认、HR 要简历、待回复三个数字和一个统一入口；
- 最佳匹配岗位卡：突出 Top 1–3 岗位；
- 求职趋势折线图：采集、过线、投递三条趋势或可切换指标；
- AI 用量环形卡：近 7 日调用、预算和今日用量；
- 最近任务状态压缩成一条状态卡，详细日志进入 `/monitor`。

## 4. P2：建议完成的视觉与产品收口

### P2-1 二级页面尚未真正继承参考图的组件语言

`/jobs`、`/confirm`、`/resume`、`/stats`、`/monitor`、`/config` 大多仍是传统后台页面，只继承了外层 Shell、颜色和圆角。

第二轮需要统一：

- 页面标题区高度与对齐；
- 卡片圆角层级，不要所有容器都使用相同的大圆角；
- 文字层级和字号；
- 按钮主次与危险操作；
- 筛选器、空状态、表格、抽屉、标签和图表的视觉规范。

### P2-2 顶部导航和左侧导航功能重复

工作台、岗位池、投递确认、简历工作台在两个导航区域同时出现。建议：

- 顶部胶囊只承担核心流程；
- 左侧栏承担模块切换或快捷入口；
- 如果保留重复导航，移动端必须只保留其中一套；
- 二级页面顶部不要又显示一次与内容区域完全相同的标题。

`/stats`、`/monitor`、`/config` 当前顶部标题和内容标题重复，视觉上像两个页面标题。

### P2-3 空状态过于简单，页面显得未完成

`/resume` 和 `/monitor` 在无数据时留下大面积空白，只显示一句文字。

建议空状态包含：

- 简洁线性插画或图形符号；
- 一句明确状态；
- 一句解释下一步；
- 一个主操作按钮；
- 可选的 2–3 步流程说明。

例如简历工作台可增加“选择岗位 → AI 优化 → 对比修改 → 导出 PDF”的步骤指引。

### P2-4 市场分析页数据有了，但图表表达不够高级

当前主要是多个等高矩形卡片和水平进度条，卡片内部常有大量空白，缺少整体叙事。

建议：

- 第一排设置 3–4 个核心结论卡，而不是直接铺所有分类；
- 城市、薪资、学历使用不同图表形式，避免全部是同一种条形图；
- 增加“市场结论”自然语言摘要；
- 对 Top 公司和技能词使用紧凑榜单或标签云；
- 减少等高空卡，优先按内容自适应高度。

### P2-5 深色主题 Logo 对比度不足

深色主题下左上角 Logo 背景变为很浅的灰白色，但 `OJ` 仍是白色，文字几乎消失。

要求：深色主题 Logo 使用深色文字，或者保持深色 Logo 底色与白色文字。必须检查所有激活态、禁用态、边框和输入框的对比度。

### P2-6 排版偏小、偏灰，关键操作辨识度不足

大量说明文字、筛选标签和表格内容使用较浅灰色与 12px 字号。在复杂业务页中显得“轻”，但并不高级，反而降低可读性。

建议：

- 正文最低 13–14px；
- 重要副信息提高对比度；
- 大段说明只保留关键一句，其余放 Tooltip 或帮助面板；
- 危险操作不要与普通二级按钮同权重；
- 每个区域只设置一个明显主操作。

### P2-7 可访问性需要补齐

配置页存在多个只有图标、没有可访问名称的按钮。弹窗也缺少完整语义和焦点管理。

要求：

- 所有图标按钮增加 `aria-label` 和 tooltip；
- 焦点可见；
- 弹窗打开后焦点进入弹窗，关闭后回到触发按钮；
- Esc 可关闭；
- Tab 不得穿透遮罩进入背景页面；
- 支持 `prefers-reduced-motion`。

## 5. P3：工程与性能建议

1. Dashboard 构建 chunk 约 **487.73 kB**，gzip 约 **135.73 kB**，可进一步拆分页面与重型组件。
2. `DashboardPage.tsx` 仍然过大，并向其他页面导出 `JobActionCard`、`JobDetailModal`，建议拆到独立业务组件目录。
3. 不建议将 `dist` 构建产物长期提交到源码 Git，除非项目部署机制明确要求。
4. 多份 Logo 草案建议移到设计归档目录，不要与生产资源混放。
5. 图表、Dialog、筛选器等应沉淀成统一组件，避免每页自行拼装。

## 6. 推荐的第二轮执行顺序

### 第一阶段：修复可用性阻断

1. 修复所有浮层定位问题，并统一 Portal。
2. 重构岗位池表格，解决 1280px 纵向折行。
3. 给确认队列增加分页或虚拟列表。
4. 修复移动端导航和主要页面布局。

### 第二阶段：首页产品收口

1. 删除首页完整筛选器和批量岗位操作。
2. 将任务运行状态压缩为横向状态卡。
3. 重做第二排 Bento：事项、最佳岗位、趋势、AI 用量。
4. 控制 1280×720 首屏至少展示 Hero、自动化卡、流程进度和一部分优先事项。

### 第三阶段：全站视觉统一

1. 重做空状态。
2. 优化市场分析图表。
3. 统一二级页面标题、筛选器、卡片、按钮、标签和抽屉。
4. 完成深色主题与可访问性检查。
5. 最后再做微动效，不要用 transform 页面根容器影响浮层。

## 7. 最终验收标准

完成第二轮后至少满足：

- 1280×720 下所有核心页面无逐字纵向排版、无页面级横向溢出；
- 390×844 下侧栏不常驻，顶部导航不竖排，筛选器不占满长屏；
- 所有 Dialog/Drawer 在任意滚动位置均可见、可关闭、可键盘操作；
- 首页内容高度明显下降，不再复制确认页完整功能；
- 确认页不一次渲染 142 张完整卡片；
- 深色主题 Logo、正文、边框和禁用状态清晰可辨；
- `/resume`、`/monitor` 空状态具备明确下一步；
- 全站组件看起来属于同一套产品，而不只是共享同一个侧栏和圆角。
