# OpenJob 当前 UI 视觉问题分析与五项优先修复计划

> **用途：直接交给其他 UI Agent 执行**  
> **审查日期：2026-09-23**  
> **审查范围：桌面端工作台、岗位池、移动端岗位池、全局布局和视觉令牌**  
> **重要约束：本文件是视觉审查和实施计划，不要求当前 Agent 立即修改页面；必须先按优先级逐项实施和验收。**

---

## 0. 审查结论摘要

OpenJob 当前界面已经具备完整的产品视觉基础：

- 浅灰画布 + 白色应用壳；
- 左侧图标导航；
- 顶部胶囊式主导航；
- 钴蓝作为品牌强调色；
- 卡片化 Dashboard；
- 桌面端和移动端两套导航形态；
- 统一圆角、边框、过渡动效和深色主题令牌。

当前主要问题不是“缺少设计”，而是：

> **视觉元素太多都在争夺注意力，页面虽然精致，但没有形成足够强的任务优先级和信息层级。**

从用户第一眼的体验来看，当前 UI 更像“完成度较高的管理后台”，还没有完全达到“高级、丝滑、低认知负担的个人求职工作台”。

最影响视觉效果的五项按优先级如下：

| 优先级 | 问题 | 主要影响 | 建议 |
|---|---|---|---|
| P0 | 视觉焦点和页面层级不够明确 | 用户不知道当前最该做什么 | 先重排信息层级和主行动 |
| P0 | 卡片、按钮和颜色缺乏角色区分 | 页面显得“每个模块都重要” | 建立组件语义和颜色职责 |
| P1 | 间距、密度和栅格节奏不统一 | 桌面端显得松散，岗位池显得拥挤 | 建立统一 spacing/rhythm |
| P1 | 字号和文字层级不够稳定 | 标题、统计、辅助信息竞争 | 重建 Typography scale |
| P1 | 移动端信息架构仍然偏桌面化 | 导航、筛选、表格和按钮拥挤 | 移动端独立设计，不只是缩小 |

推荐实施顺序：

```text
P0-1 视觉焦点与信息层级
→ P0-2 卡片/按钮/颜色语义
→ P1-3 间距与密度
→ P1-4 Typography
→ P1-5 移动端信息架构
```

不要先做渐变、阴影、图标替换或动画增强。当前最重要的是先让用户清楚：

```text
现在处于什么状态
下一步要做什么
哪个岗位值得处理
哪个按钮会产生外部动作
```

# 2. P0-1：重建视觉焦点和页面信息层级

## 2.1 问题描述

当前 Dashboard 顶部同时出现：

- 主欢迎 Hero；
- 近 7 日活动；
- 今日自动化深色卡片；
- 计划任务；
- 今日求职流程；
- 任务状态；
- 需要处理；
- 最佳匹配；
- 近 7 日趋势。

它们的卡片样式、圆角、边框和视觉权重比较接近，导致：

- 深色“今日自动化”卡片过度吸引注意力；
- “运行全流程”“单独采集”“开启监测”等动作与“需要你处理”的候选岗位同时竞争；
- 用户进入工作台后，不容易立即知道今天最重要的下一步；
- Dashboard 更像“统计总览”，而不是“行动工作台”。

岗位池也存在类似问题：

- 筛选栏、选择、回收站、BOSS 一键投递、AI 评分、评分选项、导出等按钮同时出现；
- 多个按钮都是蓝色或强边框样式；
- “选择岗位”和“执行外部动作”的视觉区别不够强。

## 2.2 目标

每个页面只能有一个明确的第一视觉焦点和一个主行动：

| 页面 | 第一焦点 | 主行动 |
|---|---|---|
| 工作台 | 待处理求职事项 | 查看并处理高优先级岗位 |
| 岗位池 | 当前筛选后的岗位集合 | 选择岗位并进入审核/评分 |
| 投递确认 | 待用户确认的外发内容 | 确认发送，但必须视觉上最谨慎 |
| 简历工作台 | 当前岗位的材料准备状态 | 查看来源并生成/编辑简历 |
| 监测/回复 | 需要用户响应的会话 | 查看回复并人工处理 |

## 2.3 修复策略

### Dashboard 重排

建议改为四层：

```text
第一层：页面标题 + 今日一句话状态 + 一个主行动
第二层：需要你处理的任务队列
第三层：计划任务/采集/评分/投递流程状态
第四层：统计趋势和市场分析
```

建议的首屏顺序：

```text
工作台标题
→ 今日待处理数量
→ 主行动按钮“查看待处理岗位”
→ 高分岗位/待确认/待回复三个关键入口
→ 计划采集状态
→ 今日流程进度
→ 活动图表和统计
```

“今日自动化”不应该一上来成为最大的深色卡片。可以改为：

- 普通卡片；或
- 只在任务运行中使用深色高对比态；或
- 作为右侧辅助状态面板，弱化视觉面积。

### 岗位池工具栏分组

把当前一长排按钮拆成三组：

```text
选择组：选择本页 / 全选 / 清除
分析组：AI 评分 / 评分选项
输出组：放行确认 / 导出 / 回收站
```

只有当前状态允许且用户完成选择后，外发相关动作才显示为强按钮。

### 投递确认页面降噪

投递确认页的“确认发送”必须是危险操作，不应与普通查看按钮使用相同视觉重量。建议：

- 预览和编辑按钮：secondary/ghost；
- 确认发送：唯一 primary；
- 批量发送：warning/danger 风格并显示数量；
- 发送前事实校验、平台、额度和岗位数量放在确认区域上方。

# 3. P0-2：收敛卡片、按钮和颜色的语义系统

## 3.1 问题描述

当前界面存在大量：

- `rounded-module`；
- `rounded-card`；
- `bg-card`；
- `bg-surface-hover`；
- `bg-accent-soft`；
- `shadow-card`；
- `shadow-pop`；
- 黑色胶囊导航；
- 钴蓝主按钮；
- 深色自动化卡片；
- 黄色警告；
- 红色错误。

单独看每个组件都合理，但组合后出现的问题是：

- 卡片层级过多，用户不容易判断哪个是容器、哪个是可点击模块；
- 蓝色既代表品牌、选中、主操作、来源徽标、评分强调，又代表链接；
- 黑色胶囊既用于顶部导航激活，也用于部分主按钮；
- `accent-soft` 使用较多，使很多区块都像“被强调”；
- 深色自动化卡片与浅色整体界面不完全统一；
- 警告色和主品牌色在局部并置，视觉噪声偏高。

## 3.2 目标

建立明确的角色语义：

```text
品牌色：用于品牌、当前页面、主行动
状态色：只用于成功/警告/危险/运行状态
中性色：用于结构、分组、辅助信息
强调底色：只用于当前选中或需要处理的区域
```

## 3.3 组件语义建议

### 卡片只保留三层

| 层级 | 用途 | 视觉表现 |
|---|---|---|
| Module | 页面一级模块 | 大圆角、弱阴影、较大内边距 |
| Card | 模块内部内容 | 中圆角、细边框、无或极弱阴影 |
| Interactive Card | 可点击对象 | Card + hover border + 明确 focus |

禁止每个信息区块都使用大模块卡片。

### 按钮只保留四种角色

| 角色 | 用途 | 建议 |
|---|---|---|
| Primary | 当前页面唯一主行动 | 钴蓝实底或深色实底 |
| Secondary | 常规次级行动 | 白底/浅底 + 细边框 |
| Tertiary/Ghost | 查看、切换、辅助 | 无边框、低对比 |
| Destructive | 删除、拒绝、危险发送 | 红色/橙色，必须带明确文案 |

不要让同一行出现三个以上 primary-looking 按钮。

### 颜色收敛

建议保留当前基本色值，但限制使用范围：

```text
--accent：主操作、当前导航、关键链接
--accent-soft：选中态和关键提示，不作为普通卡片背景
--success：已完成、连接正常
--warning：额度、风险、待处理警告
--danger：删除、失败、不可逆动作
--ink：顶部激活胶囊或极少量品牌按钮
```

深色自动化卡片不要同时承担：

- 自动化入口；
- 发送额度；
- 日期；
- 时间窗；
- 主启动按钮；
- 主要状态说明。

可以改成浅色模块，只有运行中状态切换为深色高对比态。

# 4. P1-3：统一间距、留白和内容密度

## 4.1 问题描述

当前页面同时使用：

- `gap-1.5`、`gap-2`、`gap-3`、`gap-4`、`gap-5`；
- `p-3`、`p-4`、`p-5`、`p-6`；
- `rounded-xl`、`rounded-2xl`、`rounded-3xl`；
- Dashboard 的大块留白；
- 岗位池筛选器的高密度输入区；
- 表格行信息密集但行动按钮占用空间较大。

截图中表现为：

- Dashboard 上半屏卡片之间节奏不完全一致；
- 大卡片内部标题、说明、指标、按钮的垂直关系有时松散；
- 岗位池筛选区在桌面端占用较大高度，但实际信息密度高；
- 移动端筛选折叠后，工具栏仍然很长；
- 表格、卡片、弹窗的边距没有明显的统一节拍。

## 4.2 目标

建立一套可执行的间距等级：

```text
4px：图标与文字、标签内部
8px：同组控件、状态组
12px：字段组、卡片内部紧凑区域
16px：普通 Card 内边距
24px：Module 内边距、区块间距
32px：页面一级区块间距
```

不要在每个组件中随意选择 Tailwind 间距。

## 4.3 修复策略

### Dashboard

- 页面一级区块使用 24/32px 间距；
- 卡片内部统一 16/20px；
- 标题到说明固定 6/8px；
- 说明到指标固定 12/16px；
- 指标到行动固定 16px；
- 避免为了对齐而给空卡片设置过高固定高度。

### 岗位池

- 桌面端筛选区采用“两行筛选 + 一行结果/操作”；
- 选择和批量操作固定在同一条操作带；
- 导出、回收站等低频操作移入“更多”；
- 表格行高统一，避免一行内出现过多不同的上下间距。

### 弹窗

- 标题区、内容区、操作区固定分区；
- 操作区与内容区至少保留 20/24px 间距；
- 不要用多个 `mt-3`、`mt-4` 叠出不可预测的垂直节奏。

## 4.4 验收标准

- [ ] Dashboard 首屏各模块间距呈现 8px 基准节奏；
- [ ] 岗位池筛选区高度减少但信息不丢失；
- [ ] 桌面端操作带不再频繁换行；
- [ ] 移动端不出现密集按钮连续堆叠；
- [ ] 弹窗标题、主体、操作区结构清楚；
- [ ] 视觉上不再同时出现“过松”和“过挤”的邻近区域。

# 5. P1-4：建立稳定的中文 Typography 层级

## 5.1 问题描述

当前字体系统整体可读，但存在：

- 页面标题、模块标题、卡片标题、表格标题多处使用相近的 `font-semibold`；
- 辅助文案大量使用 `text-xs`，在移动端偏小；
- Dashboard 数字、岗位评分、状态文字都使用加粗，但缺少统一的数字等级；
- 岗位池中公司名和职位名在同一行竞争，扫描效率不高；
- 10px/11px 的标签较多，既影响阅读，也让页面显得“后台化”；
- `Inter` 放在中文字体栈前面，但中文实际仍依赖系统字体，各平台字宽和行高可能不同。

## 5.2 目标 Typography scale

建议固定以下层级：

| 层级 | 用途 | 桌面 | 移动 |
|---|---|---:|---:|
| Display | 首页主标题 | 30/36 | 24/30 |
| H1 | 页面标题 | 24/32 | 20/28 |
| H2 | 一级模块标题 | 18/26 | 16/24 |
| Body | 正文/岗位信息 | 14/22 | 14/22 |
| Meta | 时间、来源、辅助信息 | 12/18 | 12/18 |
| Micro | 极少量标签 | 11/16 | 尽量不用 |
| Metric | 核心数字 | 24-32 | 22-28 |

## 5.3 修复策略

- Dashboard 主标题只保留一处 Display；
- 页面标题统一 H1；
- 模块标题统一 H2，不要所有卡片都 `font-semibold` 后依赖大小区分；
- 岗位卡片使用两行结构：
  - 第一行：职位名；
  - 第二行：公司、地点、薪资、来源；
- 分数、待处理数、投递数使用统一 Metric 样式；
- 低于 12px 的文字只用于极少量状态标签；
- 长中文说明使用 1.5-1.7 行高，避免挤成一块灰色文字；
- 建议显式设置中文优先的字体变量，保证 Windows、macOS、移动端表现一致。

## 5.4 验收标准

- [ ] 每个页面只有一个 H1 视觉层级；
- [ ] H1/H2/Body/Meta/Micro 可一眼区分；
- [ ] 移动端辅助文字不低于 12px；
- [ ] 岗位标题扫描顺序自然；
- [ ] 数字指标比标签明显，但不会压过主行动；
- [ ] 所有重要信息不依赖超粗字重区分。

# 6. P1-5：移动端独立信息架构与触控布局

## 6.1 问题描述

当前移动端已经有底部导航和基础响应式，但从岗位池截图可以看到：

- 底部导航一次放置 7 个入口，文字只有 10px；
- 顶部胶囊导航仍保留桌面端的多个页面入口，宽度不足时容易截断；
- 岗位池筛选折叠后，批量操作按钮仍然连续堆叠；
- 表格虽然没有明显横向溢出，但移动端信息被压缩，岗位、公司、时间、状态和操作不容易快速扫描；
- 导出、回收站、评分、放行等操作与移动端主任务混在一起；
- 固定底部导航遮挡风险需要持续关注；
- 触控目标虽然部分达标，但 10px 标签和小型 ghost 按钮仍显得偏小。

## 6.2 目标

移动端不是把桌面端缩小，而是改成：

```text
移动端工作台
→ 查看今日待处理
→ 查看岗位卡片
→ 查看评分和事实来源
→ 单条审核/放行
→ 查看投递进度
```

## 6.3 修复策略

### 底部导航

建议最多保留 5 个一级入口：

```text
工作台 / 岗位 / 确认 / 简历 / 更多
```

将以下入口收进“更多”：

```text
监测 / 回复 / 配置 / 统计
```

如果暂时不改信息架构，至少：

- 缩短标签；
- 保证每个入口宽度一致；
- 文字不截断；
- 触控区域不小于 44x44px；
- active 状态同时使用图标、文字和顶部/底部指示器。

### 顶部导航

移动端隐藏或压缩桌面端胶囊导航，只保留：

- 当前页面标题；
- 返回/菜单；
- 主题切换或更多操作。

### 岗位池

移动端优先使用卡片，不使用压缩表格：

```text
公司 + 职位
评分 + 薪资 + 地点
状态 + 来源
主行动
次级操作收进更多
```

### 操作区

- 批量操作收进底部 sticky action bar；
- 只有选中岗位后才出现；
- 主操作保持一个；
- 导出/删除等低频动作进入更多菜单；
- 保证底部导航和 sticky action bar 不互相遮挡。

## 6.4 验收标准

必须用以下尺寸验收：

```text
360 × 800
390 × 844
430 × 932
768 × 1024
1280 × 900
```

- [ ] 底部导航文字不截断；
- [ ] 所有主要触控目标至少 44×44px；
- [ ] 岗位卡片不用横向滚动才能看全；
- [ ] 评分、薪资、地点、状态和主行动一屏可见；
- [ ] 底部导航不会遮住最后一条岗位或 sticky action bar；
- [ ] 顶部不会同时出现桌面导航和移动导航的竞争层级；
- [ ] 长公司名、职位名、来源标签可优雅截断或换行；
- [ ] 深色主题和浅色主题均通过。
