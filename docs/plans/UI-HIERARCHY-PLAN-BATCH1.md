## 一、工作台（DashboardPage）

### 现状问题（实测）

首屏同屏出现 9 个视觉块：Hero、周活动图、深色自动化卡、计划任务、流程进度、任务状态、需要处理、最佳匹配、趋势图——全部 `rounded-module` + 相近边框阴影，深色卡最抢眼但不是用户最该看的。

### 新信息层级（四层）

```text
L1 焦点层（首屏上半）
  ├─ 页面标题「工作台」+ 今日一句话状态
  │   例：「3 个岗位等你确认 · 1 个 HR 在等你回复 · 48 条招呼语待发送」
  ├─ 唯一主行动按钮：「查看待处理岗位」→ /confirm（数量 >0 时显示；为 0 时
  │   主行动变为「开始今日采集」）
  └─ 三个关键数字入口（可点击，非卡片）：待确认 12 · 待回复 3 · 待发送 48

L2 行动层（你今天要做的事）
  ├─ ActionItemsCard（需要处理）：保持，升为 L2 首位
  ├─ PriorityItemsCard（优先岗位）：并入 ActionItemsCard 同区或紧随其后
  └─ 待发送招呼语提示（48 条已审阅待发）——新引流入口

L3 流程层（系统状态，弱化）
  ├─ AutomationControlCard：深色 → 浅色常规卡；仅任务 running 时切深色高对比
  ├─ ScheduledCollectionCard：保持，缩小视觉面积
  └─ PipelineProgress（流程进度）：保持

L4 分析层（折叠或下沉）
  ├─ TrendsChart / WeeklyActivityChart：合并为一张图表卡
  ├─ BestMatchCard：降级移入岗位池（它本质是岗位列表入口）
  ├─ UsageDonutCard：移入配置页或折叠
  └─ 队列健康卡：并入 L2 行动层（它是行动提示不是统计）
```

### 变更明细

| 卡片 | 现状 | 新层级 | 动作 |
| --- | --- | --- | --- |
| DashboardHero | 含 3 个启动按钮 + 欢迎语 | L1 | 保留标题区；按钮组精简为 1 个主行动 + 1 个 ghost「开始采集」 |
| AutomationControlCard | 深色大卡抢焦点 | L3 | 默认浅色；running 时深色；移除与 Hero 重复的启动按钮 |
| ActionItemsCard | 与 PriorityItems 并列 | L2 首位 | 升级为主区 |
| BestMatchCard | 第二排大卡 | 降级 | 移入岗位池（点击即筛选高分） |
| TrendsChart/WeeklyActivity | 两张图 | L4 合并 | 一张图卡 |
| UsageDonutCard | 第三排 | L4 | 移入配置或折叠 |
| 队列健康卡 | ActionItems 下方 | L2 | 上移与 ActionItems 同组 |

### 唯一主行动

**「查看待处理岗位」**（数字 >0 时）；数字全 0 时主行动变「开始今日采集」。页面其余按钮全部降为 secondary/ghost。

## 二、岗位池（JobsPoolPage）

### 现状问题（实测）

筛选条 + 回收站 + 一键投递 + AI 评分 + 评分选项 + 导出（3 种）+ 放行筛选结果 + 全选筛选结果 + 已选择 N + 清空 + 移入回收站 + 放行已选 + 分页……同一工具栏区域 10+ 个按钮，多为 secondary/ghost 同权重；用户分不清「选择类」「分析类」「外发类」。

### 新信息层级

```text
L1 焦点：筛选结果列表本身（表格），工具栏退为辅助
L2 操作带（吸顶，单行分组）：
  ├─ 选择组：全选筛选结果 (N) ｜ 清空 ｜ 已选 N 条
  ├─ 放行组（选择后才出现，primary）：放行筛选结果 ｜ 放行已选
  └─ 更多 ▾（低频收进菜单）：AI 评分 ｜ 评分选项 ｜ 导出（全部/筛选/所选）｜ 回收站
L3 筛选区（折叠默认态保持）：关键词/评分/薪资/状态/来源通道/来源平台
L4 结果区：表格（含来源徽标、回复徽章）
```

### 变更明细

| 项 | 现状 | 新层级 | 动作 |
| --- | --- | --- | --- |
| 回收站按钮 | 标题旁常驻 | 更多菜单 | 移入 |
| 一键投递（已选 N） | 与选择类按钮并列 | 发送组 | **视觉降为 warning 边框+明确文案**（发送是敏感动作不与查看竞争） |
| AI 评分/评分选项 | 常驻强按钮 | 更多菜单 | 移入 |
| 导出 ×3 | 常驻下拉 | 更多菜单 | 移入 |
| 放行筛选结果/放行已选 | ghost | 选择后升 primary | 保持（这是本页主行动） |
| 移入回收站 | destructive 常驻 | 选择后出现 | 保持 destructive 但仅选择后显示 |

### 唯一主行动

**「放行」（筛选结果/已选）**——仅当用户完成选择后升为 primary；未选择时本页无强按钮，纯浏览状态。

## 三、投递确认页（ConfirmQueuePage）

### 现状问题（实测）

双 tab（待确认生成 / 待发送招呼语）+ day_off 提示条 + 批量栏 5 按钮 + 岗位卡网格 + 弹窗×3。「确认发送」是外发动作，但与「查看详情」「编辑招呼语」等 ghost 按钮视觉重量接近；day_off 提示条常驻黄色易被无视。

### 新信息层级

```text
L1 焦点：待确认/待发送岗位卡片列表
L2 阶段提示层：
  ├─ 阶段指示器：「① 生成招呼语 → ② 人工审阅 → ③ 确认发送」（当前阶段高亮）
  ├─ day_off 提示条（仅当天显示，带图标）
  └─ 阶段专属批量栏：
      ├─ 待确认生成 tab：全选筛选结果 ｜ 清空 ｜ 生成已选（primary，文案明确"只生成不发送"）
      └─ 待发送招呼语 tab：全选 ｜ 清空 ｜ 确认发送已选 N（**唯一 warning/danger 风格**，
          文案"确认发送 N 条，不可撤回"）
L3 内容层：岗位卡（生成 tab）/ 招呼语全文卡（发送 tab）
L4 弹窗层：六要素确认框（生成/发送文案区分已做）｜ 详情 ｜ 编辑
```

### 变更明细

| 项 | 现状 | 新层级 | 动作 |
| --- | --- | --- | --- |
| 确认发送按钮 | 与编辑按钮同权重 | L2 唯一强按钮 | **warning 实底**（非 primary 蓝），文案含数量+不可撤回 |
| 编辑/查看详情按钮 | secondary | L3 卡内 ghost | 降权 |
| day_off 提示条 | 常驻顶部黄条 | L2 | 保持但加图标与"明日恢复"说明（已做） |
| 超期退出按钮 | 与放行并列 | 更多菜单 | 移入（低频操作） |

### 唯一主行动（按 tab 分）

- 待确认生成 tab：**「生成已选 N 条招呼语」**（primary 蓝，文案明确不发送）
- 待发送招呼语 tab：**「确认发送已选 N 条」**（warning 橙/红实底，唯一外发动作）

## 四、全局组件语义（P0-2 预告，确认后实施）

- 按钮四角色：Primary（蓝实底，每屏唯一）/ Secondary（白底细边）/ Ghost（无边框）/ Warning-Send（发送类专属橙实底）
- 卡片三层：Module（页面区块）/ Card（内容）/ Interactive（可点击，hover 边框）
- 深色卡仅用于「任务运行中」状态
- 颜色职责：accent=品牌与主行动；accent-soft 仅选中态；success/warning/danger 仅状态；ink 仅导航激活

## 五、需要你确认的决策点

1. **BestMatchCard 移入岗位池**：它本质是高分岗位入口，移到岗位池更合理——同意吗？
2. **AI 评分按钮移入「更多」**：评分是低频动作（有定时采集自动评），移入后手动评分路径多一层——接受吗？
3. **待发送招呼语的「确认发送」用 warning 橙底**（而非蓝色）——发送是外发+不可撤回动作，橙色警示更符合"确认发送，但必须视觉上最谨慎"的定位——接受吗？
4. **Dashboard 图表合并**：趋势图+周活动图合并为一张（减少图表数量）——保留哪个图表类型你偏好？
