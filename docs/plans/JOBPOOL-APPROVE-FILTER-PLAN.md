# 岗位池批量放行增强计划（筛选 + 跨页全选 + 一键放行）

> **日期**：2026-09-22 ｜ **触发原因**：用户体验岗位池"放行到确认队列"时发现——筛选"已过滤"岗位后只能逐页全选（15 条/页），几百个岗位操作繁琐。
> **目标**：筛选出"已过滤待人工判断"的岗位 → 跨页一次全选 → 一键批量放行，全程不离开岗位池。

---

## 1. 现状盘点（已实测）

| 能力 | 现状 |
| --- | --- |
| 筛选"已过滤"状态 | ✅ **已有**——岗位池筛选条"岗位状态"下拉选「已过滤」即可（用户可能没注意到） |
| 全选 | ⚠️ 只有"全选本页结果"（15 条/页），跨页需逐页操作 |
| 批量放行 API | ✅ 已支持（`/api/jobs/bulk-approve`，单次上限 1000，只对「已过滤」状态生效，其他状态自动跳过并给原因） |
| 评分/来源筛选 | ✅ 评分下限、来源平台（BOSS/智联/51job）筛选已有 |

**结论**：后端与筛选器基本齐备，缺口集中在前端的"跨页全选"体验。

## 2. 方案（三个改动，全部前端为主）

### 改动一：「全选筛选结果」按钮（跨页全选）

批量栏在"全选本页结果"旁新增**「全选筛选结果 (N)」**：

- 点击后按当前筛选条件从 `/api/jobs/search?limit=1000` 拉取全部匹配岗位的 id；
- 全部收进 selectedIds（上限 1000，与后端 bulk-approve 一致）；
- 跨页勾选状态保持，翻页不丢。

### 改动二：「放行筛选结果」一键放行（免勾选直达）

批量栏新增**「放行筛选结果」**按钮（一键流程）：

1. 点击后弹确认框，**先预览**：筛选结果总数 / 其中「已过滤」状态数 / 将被跳过数（非 filtered 状态）；
2. 确认后直接调 `bulk-approve`，不需要先勾选；
3. 完成后提示成功数与跳过原因分布。

### 改动三：筛选结果计数条

批量栏常显：**「筛选结果 N 个 · 其中已过滤待放行 M 个」**——放行前先看到量级，避免误放几百个。

## 3. 不改的东西

- 后端 `bulk-approve` 逻辑（已满足）；
- 单岗位"放行"按钮（保留，适合个别操作）；
- 分页机制（跨页全选后翻页查看仍正常）。

## 4. 安全边界（不变）

- 放行 API 只对「已过滤」状态生效，其他状态跳过；
- 放行 ≠ 发送：岗位进入确认队列后仍需生成招呼语 → 人工确认 → 才能发送；
- 单次上限 1000，防止误操作全库。

## 5. 测试

- UI：筛选"已过滤"→ 全选筛选结果 → 数量正确；放行确认弹窗预览数量；
- 后端（已有）：bulk-approve 只放行 filtered、跳过原因、1000 上限。

## 6. 涉及文件

- `JobsPoolPage.tsx`（批量栏 + 全选逻辑 + 确认弹窗）
- 无后端改动、无数据库改动
